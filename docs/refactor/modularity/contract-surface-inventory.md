Generated by `tools/ContractSurfaceAudit` — **do not hand-edit**. Re-run
`dotnet run --project tools/ContractSurfaceAudit` to refresh after analyzer changes.

Phase 0 item 1 (see [phase-0-foundation.md](phase-0-foundation.md)): for every `IAnalyzer` implementation, what it touches outside its own file — constructor parameters, `AnalysisContext` members read, `IHeapAnalysisCache` members called, and `internal` types reached only because `DumpDetective.Core`/`DumpDetective.Platform` grant `DumpDetective.Analysis` `InternalsVisibleTo`. This is exactly the surface Phase 1's SDK must expose — nothing more.

Detection is syntax-only regex over each analyzer class's own text (no MSBuild/semantic model), matched against the real member lists of `IHeapAnalysisCache` and the real `internal` type declarations below. False positives are possible where an unrelated identifier collides with one of these names; false negatives are possible where a member is reached through an intermediate local/field alias rather than `context.` directly. Treat this as a starting inventory to verify per-analyzer during migration, the same standard the project already applies to this kind of audit ([modularity-plan.md § 10 point 8](../modularity-plan.md#10-external-review-2026-09-08--where-this-can-be-questioned)).
